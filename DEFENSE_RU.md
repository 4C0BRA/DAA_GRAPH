## Разобрать алгоритмы своими словами

### DSU

Храню parent и size. `find(x)` находит представителя множества. Во время поиска делаю path halving: parent[x] = parent[parent[x]]. `union(a,b)` объединяет множества, подвешивая меньшее дерево к большему. Если представители совпадают, объединение не нужно: в Kruskal такое ребро образует цикл. Амортизированная сложность O(α(V)), а не строго O(1) для каждого вызова.

### Kruskal

Сортирую все рёбра по возрастанию веса. Принимаю ребро, только если оно соединяет разные DSU-компоненты. Когда приняты V−1 рёбер, связный граф уже соединён. Корректность следует из cut property: самое дешёвое ребро через разрез можно включить в некоторый MST. Сортировка даёт O(E log E), плюс инициализация O(V). На несвязном графе получаю минимальный остовный лес.

### Prim

Начинаю с одной вершины, кладу исходящие рёбра в min-heap. Извлекаю самое дешёвое ребро к ещё не посещённой вершине, добавляю эту вершину и её кандидатов. Ребро к уже посещённой вершине пропускаю. Для несвязного графа запускаю то же из следующей непосещённой вершины. В моей lazy-версии heap может содержать O(E) рёбер: время O(V + E log(E+1)), дополнительная память O(V+E).

### Kahn: топологический порядок

Считаю входящие степени. Кладу в очередь все вершины с indegree = 0. Извлекаю вершину, добавляю в ответ, уменьшаю indegree её соседей. Если обработал меньше V вершин, есть цикл. Почему? В оставшемся подграфе у каждой вершины есть входящее ребро; следуя по предшественникам в конечном графе, обязательно повторю вершину. Время O(V+E).

### Kosaraju: SCC

SCC — максимальная группа вершин, где из любой можно добраться в любую другую. Первый DFS записывает вершины по времени завершения. Затем разворачиваю все рёбра и делаю DFS в обратном порядке завершения. Каждый новый поиск даёт одну SCC. Важно записывать именно завершение DFS, а не момент первого посещения. Реализовал DFS через стек и индекс следующего ребра, без рекурсии. Время и дополнительная память O(V+E).

### Dijkstra

dist[source] = 0, остальные расстояния — бесконечность. Извлекаю вершину с минимальным известным расстоянием, проверяю исходящие рёбра. Relaxation: если dist[u] + w < dist[v], обновляю dist[v] и parent[v], добавляю новую запись в heap. Устаревшие записи пропускаю. Неотрицательность весов гарантирует, что дальнейший обход не уменьшит уже минимальное расстояние. Путь восстанавливаю по parent назад, потом переворачиваю.

## Пример руками

Неориентированные рёбра: 0–1:4, 0–2:2, 1–2:1, 1–3:5, 2–3:8, 3–4:2.

Kruskal принимает 1–2:1, 0–2:2 и 3–4:2. Пропускает 0–1:4: его концы уже в одной компоненте. Принимает 1–3:5. Итого 1+2+2+5 = 10.

Dijkstra из 0: расстояния [0,3,2,8,10]. Путь до 4: 0→2→1→3→4. После обработки 0 dist[1]=4; после обработки 2 он становится 3. Это пример relaxation и появления устаревшей записи (1,4) в heap.

Направленные рёбра 0→1, 1→2, 2→0, 2→3, 3→4 дают SCC {0,1,2}, {3}, {4}. Топологический порядок исходного графа невозможен. Если сжать каждую SCC в одну вершину, получится DAG.

## Частые вопросы и короткие ответы

**MST и shortest paths — одно и то же?** Нет. MST минимизирует сумму рёбер, соединяющих все вершины. Dijkstra минимизирует расстояние от источника до каждой вершины. Например, в треугольнике 0–1:2, 1–2:2, 0–2:3 MST имеет сумму 4, но путь 0→2 в нём длиной 4, хотя прямой путь длиной 3 короче.

**Почему у Prim и Kruskal могут отличаться рёбра?** При равных весах MST может быть несколько. Оптимальная сумма совпадает, конкретный набор рёбер — необязательно.

**Может ли MST иметь отрицательные веса?** Да. Запрет отрицательных весов относится к Dijkstra, а не к MST.

**Почему нельзя Dijkstra с отрицательными рёбрами?** Пример: 0→A:2, 0→B:5, B→A:−10. Ранняя фиксация A с расстоянием 2 неверна: настоящий ответ −5. Для общих отрицательных весов нужен Bellman–Ford. Мой код отклоняет отрицательные веса заранее.

**Почему не BFS для расстояний?** BFS минимизирует число рёбер и подходит для одинаковых весов. Для разных неотрицательных весов использую Dijkstra.

**Что если вершина недостижима?** Расстояние равно Long.MAX_VALUE, путь пустой. В экспериментах все достижимы из 0; недостижимость отдельно проверяется тестами.

**Почему не matrix?** Для разреженных графов adjacency list хранит O(V+E) элементов вместо O(V²) и позволяет обходить только существующие рёбра.

**Зачем фиксированный seed?** Чтобы одинаковые параметры давали тот же граф и другой человек мог повторить эксперимент. Seed не фиксирует время выполнения.

**Почему пять запусков и прогрев?** Пять требует задание; прогрев уменьшает влияние JIT. Но он не устраняет GC и планировщик, а пять запусков недостаточно для уверенных общих выводов.

**Что именно считаешь?** Просмотры рёбер, вызовы компаратора сортировки/heap, find/union и вставки/извлечения heap. Это не число всех процессорных операций. Union вызывает два find, поэтому их суммы частично описывают вложенную работу.

**Почему циклическая топологическая проверка быстрее?** В сгенерированном графе есть цикл через все вершины, поэтому ни у кого нет indegree=0. После подсчёта степеней алгоритм сразу обнаруживает невозможность полного порядка. Это особенность входных данных.

**Почему SCC просматривает 3E рёбер?** Первый DFS, построение транспонированного графа, второй DFS. Это всё ещё O(V+E), константу 3 в Big-O не пишем.

**Почему Kruskal быстрее в большом замере?** В этом запуске у Prim больше heap-сравнений и он опустошает heap. Kruskal прекращает просмотр отсортированных рёбер после V−1 принятых. Это результат конкретной реализации и графов, не универсальный закон.

**Можно по этим двум графикам отдельно оценить влияние V и E?** Нет: они менялись вместе. Для этого надо отдельно фиксировать V и менять E, затем наоборот.

**Как доказать правильность тестами?** Тесты не заменяют доказательство. Они проверяют реализацию: для маленьких MST полный перебор, для SCC независимая достижимость, для расстояний Bellman–Ford и стоимость восстановленных путей.
